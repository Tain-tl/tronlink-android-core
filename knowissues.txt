# tronlink-android-core known accepted issues

## Scan report 2026-07-14 (slash)

- S-04 (MEDIUM): scrypt parameter combination can allocate ~8 GiB before MAC verify.
  Accepted: keystore import is app-internal only; KeyStoreUtils has no external/untrusted
  caller path for attacker-supplied JSON. Scan report 2026-07-14.
  Location: KeyStoreUtils.decryptToByte (scrypt n/r/p checks)

- S-08 (MEDIUM): Illegal hex nibble not rejected in Numeric.hexStringToByteArray;
  Character.digit(-1) silently packs wrong bytes. Accepted: dirty input comes from
  upstream DApp/DeepLink/WC; app not primary owner of malformed typed-data; fix has
  wide regression surface for limited benefit. Scan report 2026-07-14.
  Location: org/tron/common/bip32/Numeric.java hexStringToByteArray

- Q-04 (MAJOR): DataFormatInterceptor re-reads DataUploader.getFormatPlain() instead of
  an upload-captured Config snapshot. Accepted: metrics-only race; worst case plaintext
  stats or encrypt retry; no asset / signing path.
  Location: DataUploader.createStatDataAPI / DataFormatInterceptor.intercept

- Q-08 (MAJOR): Nested StaticStruct decode length is 0 on Android API 21-25 because
  nestedStructLength is only computed via getParameters() (API 26+). Accepted: product
  paths rarely decode nested StaticStruct ABI; non-nested decode unaffected.
  Location: TypeDecoder.decodeStaticStructElement

- Q-12 (MINOR): Keystore public APIs may leak undeclared RuntimeExceptions
  (JsonSyntaxException / IllegalStateException / DecoderException) despite declaring
  only CipherException/IOException. Accepted: non-blocking quality/API-contract issue;
  import UI already fails closed.
  Location: KeyStoreUtils.getPrivateWithKeyStore / getMnemonicWithKeyStore;
  WalletFile.KdfParamsDeserializer

## Scan report 2026-07-21 (slash)

- Q-11 (SUGGESTION): Hash.sha3(String) treats input as hex (not UTF-8); depends on
  Numeric.hexStringToByteArray illegal-nibble behavior (S-08). Accepted: public API
  hex contract retained; sole in-repo caller Keys.getAddress passes hex pubkey;
  UTF-8 callers must use sha3String; validating/renaming risks regressions.
  Scan report 2026-07-21.
  Location: org/tron/common/crypto/Hash.java sha3(String)

- S-04 (LOW): ECKey.getPrivKeyBytes/getPrivateKey allocate a new 32-byte private-key
  array with no zeroing contract; copies remain on heap until GC. Accepted: exposure
  is process-memory only; BigInteger/BCECPrivateKey root material is immutable and
  cannot be wiped; changing accessors or call-site wipe logic risks signing/keystore
  paths for limited benefit. Scan report 2026-07-21.
  Location: org/tron/common/crypto/ECKey.java getPrivKeyBytes / getPrivateKey

- Q-03 (MINOR): TypeDecoder.asBigInteger has duplicate Double/Float instanceof and
  Float→BigInteger via doubleValue loses precision. Accepted: dead duplicate checks;
  Float is not a normal ABI numeric input; product risk negligible. Scan report
  2026-07-21.
  Location: org/tron/common/crypto/TypeDecoder.java asBigInteger

- Q-07 (LOW): ByteArray.toBytesPadded lacks null guard and throws bare RuntimeException
  on oversized input. Accepted: no in-repo callers (Numeric.toBytesPadded used instead);
  helper robustness only, no asset/signing path. Scan report 2026-07-21.
  Location: org/tron/common/utils/ByteArray.java toBytesPadded

## Scan report 2026-07-27 (jacky)

- Q-03 (MAJOR): ABI scalar illegal values soft-coerced (DecimalUtils→0, CoderNumber
  truncates decimals, CoderBool non-true/1→false). Accepted: strict parse breaks
  existing UI/DApp amount input paths; keep soft coerce + one-line accepted comments.
  Scan report 2026-07-27.
  Location: DecimalUtils.toBigDecimal; AbiUtil.CoderNumber/CoderBool.encode

- Q-06 (MAJOR): Signed Int/Fixed range uses bitLength()<=bitSize (off-by-one vs
  [-2^(n-1), 2^(n-1)-1]). Accepted: same rule as upstream web3j IntType; keep
  parity, do not tighten signed bounds. Scan report 2026-07-27.
  Location: IntType.isValidBitCount; FixedPointType.isValidBitCount

- S-04 (MEDIUM): Bouncy Castle 1.69 ASN.1 OID DoS (CVE-2025-8885) reachable via
  public ECKey.verify(byte[],byte[],byte[]) → decodeFromDER. Accepted: upgrade
  has wide crypto regression surface; verify usually sees wallet-bounded DER.
  Scan report 2026-07-27.
  Location: core/build.gradle bcprov-jdk15on:1.69; ECKey.verify / decodeFromDER

Q-14 (scan 2026-07-29): Accepted without behavior changes. Bip32ECKeyPair and
  ABI Array remain aligned with LFDT-web3j upstream. ECKey cached byte getters and
  the legacy public BIP39 word array retain their existing API behavior to avoid
  crypto, ABI, and source-compatibility regressions.
Q-02 (scan 2026-07-29): TransactionUtils.setTimestamp keeps its legacy behavior.
  Changing timestamp selection would alter serialized raw_data, transaction hashes, and
  signing inputs, so the compatibility/regression risk is higher than accepting the finding.

## Scan report 2026-08-03 (slash)

- S-04 (MEDIUM): ABI byte offsets can overflow when converted to hex-character indexes.
  Accepted: malformed RPC or contract return data can abort ABI decoding but cannot mutate
  assets or sign/broadcast; a defensive fix needs caller-contract and DynamicStruct-safe
  handling. Scan report 2026-08-03.
  Locations: org/tron/common/crypto/TypeDecoder.java;
  org/tron/common/crypto/DefaultFunctionReturnDecoder.java

- Q-01 (MAJOR): TransactionUtils.setTimestamp retains its legacy parameter behavior.
  Accepted: network expiration validation limits practical impact, while changing raw_data,
  transaction IDs, and signing inputs has higher compatibility risk. Scan report 2026-08-03.
  Location: org/tron/common/utils/TransactionUtils.java setTimestamp

- Q-04 (MAJOR): TriggerLoad displays signed intN words as unsigned values and retains ABI
  padding when displaying bytesN. Accepted: negative intN parameters are uncommon and the
  bytesN difference is display-only; calldata, signing, broadcasting, and on-chain asset
  execution remain unchanged. Scan report 2026-08-03.
  Location: org/tron/common/utils/TriggerLoad.java parseDataBytes

- Q-16 (MINOR): ECKey.equals retains asymmetric private/public-only comparison behavior.
  Accepted: there are no in-repo equality or collection callers, while changing the public
  crypto API equality semantics has higher compatibility risk. Scan report 2026-08-03.
  Location: org/tron/common/crypto/ECKey.java equals

- S-08 (LOW): Metrics address, UID, balance, and transaction profile remain plaintext in
  the Room database. Accepted: the app sandbox and allowBackup=false protect this
  metrics-only cache; encryption requires host-managed keys and a migration.
  Location: org/tron/metrics/dao/MetricsDatabase.java

- Q-08 (MAJOR): Metrics upload does not interpret the response business code. Accepted:
  cache deletion already requires the existing data.txt confirmation, while the backend
  success-code contract is not defined in this repository and guessing it could prevent
  legitimate acknowledgements.
  Location: org/tron/metrics/reporter/DataUploader.java

- Q-09 (MAJOR): Metrics upload prepares all updated rows in one batch. Accepted: paging
  requires coordinated per-batch acknowledgement semantics across DAO, repositories, and
  uploader; current failures retain the metrics-only cache for a later retry.
  Location: org/tron/metrics/reporter/DataPreparationManager.java

- Q-13 (MINOR): uid_mapping has no database unique index on address. Accepted: adding one
  safely requires duplicate reconciliation plus atomic insert-or-query migration semantics;
  the repository-wide lock covers normal in-process app access.
  Location: org/tron/metrics/bean/UIdMappingEntity.java

- S-01 (HIGH): EIP-712 multidimensional arrays are flattened and hashed once, losing
  nesting boundaries, so structurally different values of one declared type can share a
  field hash and multidimensional hashes do not match standard verifiers. Accepted:
  mirrors upstream web3j StructuredDataEncoder behavior; 1-dimensional arrays (the
  practical dapp case) are encoded per spec. Scan report 2026-08-03.
  Location: org/tron/common/crypto/StructuredDataEncoder.java encodeData
